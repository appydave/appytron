A new AppyTron app opens cream, not black

Today the AppyTron starter window is near-black with indigo and green buttons. The AppyDave brand is light-only, so every app built from it starts off-brand and gets re-skinned by hand, as FliCast and Teletubby both were.

Sample: the template's own starter window, 1100 x 760Size: ~30–45 min for one coderStatus: draft brief, not authorised to build

Where it hurts

1Scaffold a new desktop appToday: it opens near-black, Tailwind's default greys.
2It looks like someone else's appToday: no AppyDave colour or font anywhere in the template.
3Re-skin it by handToday: FliCast and Teletubby each built their own light theme.

What happens to existing apps

Nothing. create-appytron's upgrade sorts each template file into a tier, and every file this job edits is one the upgrade never touches.

FliCast and Teletubby are already light (FliCast uses #faf5ec 13 times; Teletubby uses its own bg-canvas text-ink tokens), so leaving them alone is right. The last row is why this job stays out of window-manager.ts: both apps have customised that file, and the upgrade would replace it.

The spec

What the job is

CanvasThe window background is cream #faf5ec, text is brown #342d2d, color-scheme: light.
Theme tokensAn @theme block in the template's index.css holds the AppyDave palette, so apps use names like bg-canvas, not hex.
CardsWhite cards on cream with a warm border #d4cdc4, in place of black with dark-grey borders.
Buttons"Send ping" is the one yellow CTA; "Increment" is an outlined brown button. No indigo, no emerald.
FontsOswald for headings, Roboto for body, Roboto Mono for values, loaded from inside the app (the page's security policy blocks Google Fonts).
BehaviourUnchanged: same three cards, same IPC calls, same drag strip.
Existing appsUntouched by an upgrade (renderer files are tier never).

Out of scope

  • Re-skinning existing apps — they are already light, and the upgrade leaves them alone.
  • A theme prompt in create-appytron — the AppyStack sibling (CT-0011) asks the same question; decide once.
  • The window-manager.ts auto-overwrite risk to FliCast and Teletubby — its own ticket.

What I checked, and what I didn't

  • template/src/renderer/src/App.tsx:13 — bg-neutral-950 text-neutral-100; borders neutral-800 at :30, :50, :62; buttons bg-indigo-600 :55 and bg-emerald-600 :70; 15 neutral- classes in all.
  • template/src/renderer/src/index.css:1-24 — only the Tailwind import and drag-region classes; no theme at all.
  • template/src/renderer/index.html:6-9 — CSP default-src 'self', no font-src: Google Fonts would be refused.
  • template/src/main/window-manager.ts:22,37 — window is created hidden and shown on ready-to-show, so there is no dark flash to fix with backgroundColor. index.ts:52 opens 1100 x 760.
  • create-appytron/src/lib/classify.ts:8-43 and upgrade.ts:50,90 — tiers as in the table above. Six apps carry appytron.json: FliCast, Teletubby, FliCut, FliEdit, Samantha, ImageDrip.
  • Not checked: the template was not built or launched, so I have not seen how Tailwind v4 picks up the new @theme names inside electron-vite, or how the bundled fonts land in the packaged .app. If fonts need build config, the job grows by ~15 min.

Choices for David

Brand fonts: bundle them, or use system fonts?

Bundle Oswald / Roboto / Roboto Mono as npm font packages (works offline, adds ~1 MB), or relax the security policy to allow Google Fonts, or skip fonts and keep the system font with brand colours only.

Bundle them. A desktop app should not need the internet to look right, and loosening the security policy for fonts is the wrong trade.

Build this now, or wait for AppyStack CT-0011?

Ship AppyTron alone now, or do both templates in one pass so the token names match.

Now, but copy the token names from the staff-payments theme CT-0011 already points to, so the two templates line up without waiting.
